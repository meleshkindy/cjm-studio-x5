# CJM Studio

Приложение для создания и ведения карт клиентского пути. Рабочие данные хранятся в PostgreSQL, а резервные копии и первичный перенос из прежних версий выполняются через переносимый SQLite-файл.

## Готовые функции

- реестр CJM с поиском и фильтрами по компании и актору;
- структура «стадия → шаг → действие» с нумерацией и drag-and-drop;
- процессный набор иконок: `FolderTree` для стадии, `Route` для шага, `MousePointerClick` для действия;
- основной, дополнительный и альтернативный пути между шагами;
- запрет циклов и связей от более позднего шага к более раннему;
- поля действия, состояния AS IS / TO BE, участники, системы и открытые вопросы;
- Rich Text в полях «Цель», «Смысл действия», «Боли и проблемы» и «Последовательность выполнения»: заголовки, списки, цитаты, форматирование, кликабельные HTTP(S)-ссылки и локальные изображения;
- инициативы Live, Future, Gap и MVP1–MVP3 со связью на шаг или конкретное действие;
- интерактивная карта CJM;
- отмена и повтор изменений в текущем сеансе;
- именованные редакции, сравнение и восстановление с автоматической версией перед откатом;
- резервная копия всей базы, редакций и изображений в одном SQLite-файле;
- светлая и тёмная темы по настройке операционной системы;
- адаптивный интерфейс;
- многопользовательский вход через Keycloak/OIDC с PKCE S256;
- роли `admin`, `editor`, `viewer` и назначение доступа к компаниям или отдельным CJM;
- серверная проверка JWT и короткоживущая HttpOnly-сессия для защищённых ресурсов;
- имя вошедшего пользователя в комментариях, редакциях и истории изменения CJM.

Экспорт в PDF и произвольные вложения намеренно не реализованы согласно итоговым требованиям.

## Запуск

### Авторизация и многопользовательский режим

Авторизация включается, когда заданы параметры Keycloak (или явно указано `CJM_AUTH_ENABLED=true`):

```text
VITE_KEYCLOAK_URL=https://key-stage.x5.ru/auth
VITE_KEYCLOAK_REALM=X5
VITE_KEYCLOAK_CLIENT_ID=idp_axiosdc92b_O7k
VITE_RESTORE_PASSWORD_URL=https://sts2.x5.ru/adfs/portal/updatepass
```

Параметры `VITE_*` здесь читаются исполняемым Go-файлом во время запуска, поэтому смена Keycloak не требует пересборки frontend. Поддерживаются также имена `CJM_KEYCLOAK_URL`, `CJM_KEYCLOAK_REALM`, `CJM_KEYCLOAK_CLIENT_ID` и `CJM_RESTORE_PASSWORD_URL`.

Клиент Keycloak должен быть публичным: Client authentication — Off, Standard Flow — On, PKCE — S256. Для локальной проверки добавьте точные адреса приложения в `Valid Redirect URIs` и `Web Origins`, например:

```text
http://127.0.0.1:8080/*
http://localhost:8080/*
```

В токене распознаются realm-роли или client-роли `admin`, `editor`, `viewer`. Если ни одна из них не найдена, применяется безопасная роль `viewer`. Первый администратор должен получить роль `admin` в Keycloak. После первого входа пользователя администратор увидит его в разделе «Пользователи» и сможет назначить доступ:

- компания — ко всем её текущим и будущим CJM;
- отдельная CJM — только к выбранной карте;
- `admin` всегда имеет полный доступ;
- `editor` может изменять назначенные данные;
- `viewer` работает только в режиме просмотра.

Если параметры Keycloak не заданы, приложение сохраняет локальный режим администратора для разработки и импорта данных. Для принудительного отключения используйте `CJM_AUTH_ENABLED=false`.

### PostgreSQL

Для локальной разработки можно запустить PostgreSQL из приложенного `compose.yaml`:

```bash
docker compose up -d postgres
```

Строка подключения передаётся через `CJM_DATABASE_URL` (также поддерживается стандартная переменная `DATABASE_URL`):

```text
postgres://cjm_studio:cjm_studio@localhost:5432/cjm_studio?sslmode=disable
```

Чтобы не хранить пароль в командной строке, поместите строку подключения единственной строкой в файл:

- Windows: `%AppData%\CJM Studio\postgres-url.txt`;
- macOS: `~/Library/Application Support/CJM Studio/postgres-url.txt`.

Можно выбрать другой файл флагом `--database-url-file` или переменной `CJM_DATABASE_URL_FILE`.

Для внешнего PostgreSQL создайте пустую базу и пользователя с правами на создание таблиц. Схема создаётся автоматически при первом запуске.

### Windows

Задайте подключение и откройте `dist/cjm-studio-windows-amd64.exe`. Приложение выберет свободный локальный порт и откроется в браузере.

```powershell
$env:CJM_DATABASE_URL = 'postgres://cjm_studio:cjm_studio@localhost:5432/cjm_studio?sslmode=disable'
.\dist\cjm-studio-windows-amd64.exe
```

### macOS

Выберите файл для архитектуры компьютера:

- Apple Silicon: `dist/cjm-studio-macos-arm64`;
- Intel: `dist/cjm-studio-macos-amd64`.

В Terminal разрешите запуск и запустите файл:

```bash
chmod +x ./dist/cjm-studio-macos-arm64
export CJM_DATABASE_URL='postgres://cjm_studio:cjm_studio@localhost:5432/cjm_studio?sslmode=disable'
./dist/cjm-studio-macos-arm64
```

Файлы не подписаны сертификатом Apple. Если macOS блокирует первый запуск, разрешите приложение в разделе «Системные настройки → Конфиденциальность и безопасность».

Если PostgreSQL пуст и импорт не указан, при первом старте создаются справочники и демонстрационная CJM на 5 стадий.

### Перенос существующей SQLite-базы

Передайте прежнюю резервную копию только при первом запуске на пустой PostgreSQL:

```powershell
$env:CJM_DATABASE_URL = 'postgres://cjm_studio:cjm_studio@localhost:5432/cjm_studio?sslmode=disable'
.\dist\cjm-studio-windows-amd64.exe --import-sqlite 'C:\Backups\cjm-studio.sqlite'
```

Можно использовать переменную `CJM_SQLITE_IMPORT` вместо флага. Все идентификаторы, связи, редакции, комментарии и изображения переносятся транзакционно. Если в PostgreSQL уже есть компании, автоматический импорт пропускается, чтобы не перезаписать рабочие данные.

Для отдельного каталога временных резервных копий или фиксированного порта:

```text
cjm-studio-windows-amd64.exe --data-dir C:\CJM-Data --port 8080 --no-browser
```

## Резервное копирование

Откройте раздел «Резервные копии» и скачайте SQLite-файл. Он содержит справочники, карты, версии, комментарии и изображения Rich Text. Экспорт формируется из PostgreSQL, а восстановление проверяет целостность файла и загружает его в PostgreSQL одной транзакцией.

## Сборка из исходников

Требуются Go 1.26+, Node.js 22+ и pnpm 10+.

Windows PowerShell:

```powershell
.\scripts\build.ps1
```

macOS / Linux:

```bash
sh ./scripts/build.sh
```

Скрипты устанавливают зафиксированные frontend-зависимости, проверяют TypeScript, собирают интерфейс, запускают Go-тесты и создают исполняемый файл текущей платформы.

## Архитектура

- React 19 + TypeScript + Vite — интерфейс;
- Tiptap — безопасная структурированная модель Rich Text;
- React Flow — интерактивная карта;
- Go — локальный HTTP API и единый исполняемый файл;
- PostgreSQL через `pgx` — рабочая база данных;
- SQLite через pure-Go драйвер — формат импорта и резервных копий.

По умолчанию API слушает только `127.0.0.1`. Для серверного размещения задайте `CJM_LISTEN_ADDRESS=0.0.0.0` или флаг `--listen 0.0.0.0` и публикуйте приложение через HTTPS reverse proxy. Проверка JWT выполняется сервером по issuer и JWKS Keycloak; `client secret` приложению не требуется и не должен передаваться через `VITE_*`. API проверяет роли и область доступа на каждом маршруте, ограничивает размеры JSON/изображений/резервных копий и валидирует ссылки и структуру Rich Text.

Чтобы остановить приложение, закройте его окно Terminal/PowerShell или нажмите `Ctrl+C` в этом окне.
